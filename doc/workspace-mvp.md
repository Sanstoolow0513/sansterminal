# 工作区：当前实现与演进契约

产品目标是一个以终端为中心的单窗口开发工作台：多个工作区常驻，每个工作区拥有自己的终端组、文件树状态和编辑状态；点击任何终端即可进入它所属的工作区。保留现有 Windows Terminal 的终端、分屏、连接和窗口宿主。

本文以 `feat/workspace-mvp` 的 `a63ec32` 为审查基线，记录阶段 0 的行为契约和阶段 1 的固定标题栏改动。阶段 2 已增加[可选 Monaco 宿主验证](editor-host-probe.md)，使用临时缓冲区，尚未替换文件预览器；阶段 3～6 的常驻分组导航、文档保存和文件监听仍未实现。

## 当前体验

1. 打开开发版 `WindowsTerminalDev`。没有指定或恢复工作区时，进入欢迎页，不自动启动终端。
2. 选择“新建工作区”并输入名称，或选择“打开文件夹”。文件夹选择器不可用时可用“输入文件夹路径”。文件夹工作区的首个终端从根目录启动；未选工作区时显式新建终端会进入“未命名工作区”。
3. 点击文件夹名称展开；点击文件打开临时预览标签，双击文件固定标签。输入文件名或相对路径查找文件。清空搜索或重新进入工作区会重新枚举文件树，目前没有独立的刷新按钮。
4. 拖动侧栏、文件树和文档区域的分隔线调整宽度。文档与终端共享区域窄于 520 DIP 时自动只显示文档；加宽后恢复并排。没有文档“放大／还原”或“隐藏”按钮；关闭最后一个文档标签会收起文档区域。这些布局操作不终止终端会话。
5. 点击标签栏的主页图标或按默认绑定的 `Ctrl+Shift+N` 返回工作区页，从列表打开另一工作区。其他工作区的终端仍运行，但其终端标签被隐藏。

普通窗口的标题栏独立占据顶部空间，左侧标签的展开、收起和宽度不再影响标题栏拖动区域。终端、文件树、文档和通知均在标题栏下布局。顶部标签继续遵循 `showTabsInTitlebar` 设置；关闭该设置时使用原有系统标题栏。专注、全屏和 `showTabsFullscreen` 继续遵循现有窗口行为。

## 当前能力及限制

| 操作或状态 | 当前实现 |
| --- | --- |
| 打开已驻留工作区 | 复用工作区及已有终端；没有终端时创建一个 |
| 切换工作区 | 保留终端进程、文档标签、选中文档及面板宽度；清空搜索并重建文件树，重新读取选中文档 |
| 关闭最后一个终端 | 回到工作区主页；尚不能留在无终端的文件工作台中 |
| 工作区页的“删除” | 删除最近记录和该 ID 的持久化布局；不关闭运行中的终端，不删除项目文件，也不是关闭工作区 |
| 重启 | 最近列表单独持久化；终端布局依现有恢复设置保存并重新启动进程；文档和文件树上下文不恢复 |
| 文档 | 只读预览，没有编辑缓冲、未保存状态、保存或冲突检测 |

- 文档区域为只读 `RichEditBox`，支持 UTF-8 和 UTF-16 LE 文本，最多预览前 512 KiB。已有基础词法着色；前 128 K 字符或 6000 个着色片段之后显示普通文本。底部显示当前行，尚无行号边栏或语义语言服务。
- 文件树按需展开，每目录最多显示 500 项。底部数字是当前目录已显示的项目数，`+` 表示截断。展开路径、选中节点、滚动位置和搜索状态尚未按工作区保存。
- 搜索延迟 150 ms 后在后台执行，最多扫描 20000 项、返回 100 个匹配文件，跳过 `.git`、`node_modules`、`packages`、`bin`、`obj`、`build`。版本检查丢弃过期结果，已经开始的扫描尚不能及时取消；`packages` 可能包含 monorepo 源码，后续需改为可配置忽略规则。
- 尚无文件监听。目录展开和文档读取仍在 UI 线程上执行；语法着色分批进行。切换文档会重新读取磁盘，未保存内容、撤销栈和编辑位置均不在当前预览模型的承诺范围内。
- 最近记录、布局恢复与进程保活分别管理。恢复布局后启动的新 shell 不代表旧进程跨应用退出保活。

## 目标行为契约（分阶段实现）

| 用户操作 | 目标行为 | 实现阶段 |
| --- | --- | --- |
| 打开文件夹 | 创建或激活稳定 ID 的工作区；已驻留工作区不重复创建终端和文档 | 3 |
| 点击任意工作区的终端 | 定位已有终端，激活其工作区，恢复上下文，再将焦点交给该终端；不重建连接或进程 | 3～5 |
| 在终端执行 `cd` | 只改变终端当前目录，不改变终端归属或工作区根目录 | 3 |
| 关闭终端 | 只关闭该终端；关闭最后一个终端后仍可浏览和编辑工作区文件，允许显式新建终端 | 3 |
| 关闭工作区 | 独立操作；先处理未保存文档，并明确确认将关闭其中的终端；取消时完整保留工作区 | 3～4 |
| 从最近列表移除 | 明确使用“从最近列表移除”文案；只移除最近记录，运行状态和布局清理使用各自的操作 | 3、6 |
| 点击文件或终端 | 工作区激活状态与输入焦点分别管理；`Ctrl+C/F/S` 按焦点交给相应控件 | 2、4 |
| 切换文档／工作区 | 保留缓冲区、撤销历史及视图位置；未修改的临时预览标签可复用，修改后固定，不能被下一次预览替换 | 4 |
| 保存／关闭文档 | 保存失败保留缓冲区并反馈原因；关闭未保存文档提供保存、放弃和取消；截断预览绝不能作为完整文件回写 | 4 |
| 文件被外部修改 | 无本地修改时更新内容并尽量保留位置；有本地修改时保留双方并提示冲突；保存前校验磁盘版本 | 4～5 |
| 重启恢复 | 明确恢复工作区、布局和文档的范围及版本迁移；退出前处理未保存内容；不承诺 shell 跨退出保活 | 6 |

身份规则：工作区 ID 不依赖名称、路径或数组下标；显示名称、根目录和终端当前目录分别保存。终端生命周期不归当前页面的显隐控制。同一实际文件优先共享文档身份与缓冲区，各工作区分别保存标签顺序、选中状态和视图位置。

状态职责逐步从 `TerminalPage` 移出：`WorkspaceController` 管理归属和激活，`ExplorerService` 管理目录和搜索，`DocumentService` 与 `EditorHost` 管理文档和编辑器宿主，`ReviewService` 管理比较基准。继续复用 `Tab`、`Pane` 与现有终端连接。

## 实施顺序与验收门槛

| 阶段 | 交付内容 | 验收门槛 |
| --- | --- | --- |
| 0：行为契约 | 本文区分现状、目标和恢复语义 | 当前操作说明与代码一致；后续行为有可执行场景 |
| 1：固定标题栏 | 删除标题栏 overlay 接口、内容跨行和局部补偿间距；复用现有窗口按钮、命中测试和布局 | 应用和 UI 测试可构建；完成下述窗口验收 |
| 2：Monaco 宿主验证 | 独立 Win32 WebView2 矩形区域，离线运行 Monaco，先保留预览器 | 输入、层级、DPI、资源和生命周期全部验证后才决定采用混合宿主 |
| 3：常驻工作区导航 | 稳定 ID、分组终端导航、无终端工作区、独立关闭操作 | A/B/C 各两个终端均可直接选择；切换后 PID 相同；关闭最后一个终端仍留在工作区 |
| 4：可靠文档生命周期 | 替换只读预览器，管理缓冲区、预览标签、保存和冲突 | 未保存文本及撤销栈跨切换保留；失败不丢内容；截断文件无回写路径 |
| 5：项目浏览与审查 | 异步目录读取、树状态、监听、搜索取消和 Git 差异 | 新建文件可见，过期扫描可取消，比较基准明确 |
| 6：恢复与稳定性 | 持久化格式、迁移、恢复及资源检查 | 最近记录、布局、文档恢复可分别验证；反复切换无持续资源增长 |

阶段 2 是技术路线决策点。计划每窗口使用一个编辑器宿主，维护多个文档 Model 与独立视图状态；通过来源与参数受验证的读写消息连接原生端。验证失败时，先决定是否转向统一 Web 工作台，再推进后续 UI。不要继续把 `RichEditBox` 与手写着色扩展成编辑器，也不能以“页面加载成功”作为宿主验证完成。

宿主验证必须覆盖：分隔线拖动、最大化／全屏、跨 DPI、XAML 对话框层级；中文输入法与候选框、焦点切换、快捷键、右键和剪贴板；离线资源、语言 worker、开发包部署、反复切换时宿主数量和资源释放。

审查基准分别定义为：编辑缓冲区与磁盘、工作目录与 Git 暂存区、暂存区与 HEAD、任务开始时基准与当前结果。最后一项需要单独记录基准，不能把已有未提交修改都标记为某次 agent 的产出。语言服务器、调试器、扩展生态和任意停靠另行规划。

## 阶段 1 验收

构建和自动化结果不能替代原生窗口验证。测试时记录配置、系统缩放及结果；没有实际运行的项目记为待验证。

| 场景 | 操作与预期 |
| --- | --- |
| 左侧标签 | 分别以 `showTabsInTitlebar=true/false` 启动，展开／收起和拖宽侧栏；窗口按钮始终在标题栏内，终端顶部可见可输入 |
| 顶部标签 | 分别以 `showTabsInTitlebar=true/false` 启动，验证标题栏内标签及独立标签行的原有行为 |
| 文件与通知 | 打开文件预览、拖动两个分隔线并显示通知；文档标签顶部无 48 DIP 补偿空白，通知不覆盖终端或侧栏 |
| 原生窗口 | 拖动标题栏、双击最大化／还原、最小化后恢复；窗口按钮视觉位置与点击命中区域一致，Windows 11 Snap Layouts 可用 |
| 专注与全屏 | 切换专注模式、全屏及 `showTabsFullscreen`；隐藏标题栏后不留下空行，退出后恢复正常布局 |
| DPI 与主题 | 在不同缩放显示器之间移动，在浅／深色主题下检查按钮可见性、拖动区域、边框与内容边界 |
| 工作区 | A、B 各运行一个输出 PID 的长任务，来回切换；任务与 PID 保持，标题栏不随面板宽度漂移 |

现有 `TabTests::SideTabsPageLayout` 覆盖两种标题栏设置下的侧栏宽度、收起／展开、通知占位、专注和全屏布局；原生拖动窗口、Snap Layouts 和跨显示器 DPI 需要单独验证。

2026-09-29 验证记录：`x64 Debug` 的 `CascadiaPackage` 和 `TestHostApp` 构建通过；TAEF `*Tab*Layout*` 共 3 个用例通过（`VerticalTabViewLayout` 及 `SideTabsPageLayout` 的两组配置）。构建仍报告现有的 PRI263 本地化资源警告。这些用例验证 XAML 页面布局；后续已随阶段 2 验证包部署，并检查了同窗内容边界、最大化和最小化恢复。原生拖动、Snap Layouts 与跨屏 DPI 仍待验证。

## 整体产品验收（阶段 3～6）

打开 A、B、C 三个工作区，每个有两个 pwsh。在 A 中记录 PID、运行长任务、展开深层目录并修改文件但不保存；点击 B 的另一个 pwsh，进入 B 的文件树和编辑状态。在 B 终端新建文件，文件树自动显示。返回 A 时，PID、未保存内容、撤销历史、查看位置和目录展开状态都保留。关闭 A 的最后一个终端仍可编辑；关闭 A 工作区时明确处理未保存文档与运行中的终端，取消关闭不丢状态。

另外验证：有本地修改时让外部进程修改同一文件，保存必须提示冲突；打开超过 512 KiB 的文件不能把截断内容写回；从最近列表移除工作区不终止其终端；重启后按已声明范围恢复，不把新 shell 当作原进程。

## 构建、测试与部署

按 [构建说明](building.md)准备环境，在已执行 `Set-MsBuildDevEnvironment` 的 PowerShell 7 中运行：

```powershell
msbuild OpenConsole.slnx /t:"Terminal\CascadiaPackage,Terminal\Tests\TestHostApp" /p:Platform=x64 /p:Configuration=Debug /m
& .\packages\Microsoft.Taef.10.100.251104001\build\Binaries\x64\te.exe .\bin\x64\Debug\TestHostApp\TerminalApp.LocalTests.dll /name:*Tab*Layout*
```

构建不会更新开发包的松散 AppX 布局。需要部署时先关闭开发版终端，再运行与 Visual Studio 部署等价的工具（路径按 VS 版本调整）：

```powershell
& "C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\DeployAppRecipe.exe" src\cascadia\CascadiaPackage\bin\x64\Debug\CascadiaPackage.build.appxrecipe
```

不要直接对 `AppX\AppxManifest.xml` 重复执行 `Add-AppxPackage -Register`。开发包 `WindowsTerminalDev` 与商店版是两个应用。更多测试说明见 [TAEF](TAEF.md)。
